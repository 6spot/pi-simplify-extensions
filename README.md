# Pi Simplify Extensions

个人使用的 Pi TUI 展示扩展，基于 [minuque/pi-cc-extensions](https://github.com/minuque/pi-cc-extensions) 精简。

## 工具卡开发规范

[工具卡展示规范 v1](docs/tool-card-spec.md) 和[分类及完整样式目录](docs/tool-card-styles.md) 是已确认的开发与验收依据，并已纳入 [AGENTS.md](AGENTS.md)。工具按内容查询、命令、文件变更、计划、任务、提问六类适配；普通新工具和 MCP 使用共同兜底，Multiple Tools / Codemode 使用容器规则。分类路由集中在 `card-family.ts`，MCP 来源优先于同名原生工具，避免误报范围、状态或统计。

## 保留的功能

- Claude Code 风格工具卡、工具分组、点击展开与收起、Rich Diff
- 计划面板：`update_plan` 在 `Multiple Tools` 下保留一行完成数和当前步骤摘要；独立时展示步骤清单，展开/收起提示放在标题计数之后，不在清单底部重复；接收参数时即显示中性预览。计数只采用返回的已接受步骤，独立面板未全部完成用 `○`，全部完成才用 `✓`；分组子行的 `✓` 表示此次更新调用成功。展开可读完整内容和已有决策、变更、验证记录，保留 SoL-Pi 原有执行与结果
- Bash 面板：独立卡片标题显示真实退出码和耗时，命令单独成行；运行中和完成后预览最近 4 行输出，展开可读完整的已有输出、原生截断说明和完整输出路径。分组内保持一行命令与耗时摘要，保留失败、取消和超时原因
- Grep / Find 面板：独立卡片显示查询、范围和最多 4 行结果预览，完成标题区分匹配数、路径数、空结果及上限/截断；分组内保持一行查询与实际结果摘要
- Read 面板：运行时显示请求的读取范围，完成后显示实际返回的行号和最多 4 行内容预览，复用原生代码高亮、图片显示及展开视图，保留继续读取的位置和原始限制说明
- 原生与 Compact Thinking 思考文字统一使用低强调的中性灰；Compact Thinking 运行中默认预览 3 行，完成后保留 1 行，仍可展开全文（不再提供整回合 Compact Mode）
- 简洁代码区域：隐藏代码块头尾围栏及其语言标签，保留原生语法高亮、缩进和换行，不修改原始消息
- Codex 风格输入框：灰色背景、无边框、无前缀符号、保留原生编辑能力；底部留一行空行与 Footer 分隔，Footer 与 Working 等加载行对齐，左右各留 1 列，Footer 下方再留一行空白
- 独立在输入框上方的 Working 状态，显示当前工具操作、Token 数量和耗时；工具进行中用蓝色空心圆 `○`，成功的工具分组及独立 Codemode 容器标题用绿色实心圆 `●`，成功子项和普通单工具用绿色 `✓`，静态标记区分状态
- 单行无图标 Footer：左侧目录和 Git 分支，操作期间追加 `[rebasing 2/5]`、`[merging]` 等临时状态，结束即消失，不显示增删行数；右侧上下文百分比/窗口、费用（默认 `$0.00`，保留两位小数）、Thinking Level 与模型；字段以 ` | ` 分隔，Thinking Level 与模型用 ` · ` 连为一组，不显示 `ctx` 前缀。文字统一使用暖灰色，模型固定在最右端，终端窄时先精简项目信息
- Fullscreen 鼠标操作、回到底部、顶部固定用户消息
- `/context` 上下文查看：Token 数与百分比各列右对齐，Token 数和标题用量使用次级色；支持键盘选择与鼠标打开原文预览
- 官方 Pi 启动欢迎页，不替换 Logo

## 安装与测试

换机器时完整安装 Simplify、Subagent、question、handoff 及配套依赖，见 [跨机器安装说明](docs/install.md)。以下命令只安装 Simplify 界面与主题：

```bash
pi install git:github.com/6spot/pi-simplify-extensions
# 安装或更新后
/reload
```

重载或恢复会话后，已有工具卡片也会重新应用当前展示，包括完整 SoL-Pi 延后注册的计划工具，无需再次执行 `update_plan` 刷新旧卡片。

本地开发可在项目目录运行 `pi -e .`。检查代码可运行 `npm ci`、`npm run typecheck`、`npm test`。

在 Pi 的 `/settings` 中切换主题 `simplify-dark` 或 `simplify-light`。两者采用暖灰配色：浅色偏纸白和浅石灰，深色偏暖炭灰；工具卡与输入框用不同深浅区分，在真彩色和 256 色终端中都保留层次。工具摘要中的命令、路径和展开后的普通输入值用偏暖的灰色，以明暗层次与输出区分，行内代码与其同色；链接和进行中标记保留柔和蓝色。成功使用绿色标记，Diff 保留低饱和的增删底色和行内强调。原生和 Compact Thinking 思考文字统一使用比正文更淡的中性灰。

本扩展管理的工具卡收起时保持透明；展开后才显示中性或错误背景。输入摘要最多 2 行，普通输出最多 4 行；Bash 保留最新输出并说明隐藏的是更早内容。Plan 最多预览 6 步，Multiple Tools / Codemode 最多预览 6 项。按终端可见行预算，确实裁剪后才追加说明；只有单位和数量可靠时才报精确数字。Diff 使用专用布局，Edit 沿用配置预算，Write 默认预览 4 行；折叠正文不重复标题中的增删统计。

Subagent 的同步单任务、并行、链式和后台任务使用一致的紧凑卡片：标题显示角色、短任务、真实状态及可用耗时，运行中只预览一行最新进展，终态最多三行结果或错误。执行记录和用量放入展开详情，不在收起时重复派发标题或铺开最近多条执行记录。同步进程记录真实运行与结束状态，旧历史没有耗时时省略；重载或恢复会话后，已有子任务卡也会应用当前渲染。

工具卡展开/收起统一固定在标题末尾，包含 Edit、Write Diff，运行、完成、失败及展开状态均不改变操作所在行；分组子项共用父容器的操作，增删统计也放在标题。展开后点击标题 `Collapse` 或卡片正文任意位置均可收起，拖动选择文本时才保留展开。折叠卡正文的省略行（如 `… More output hidden`）可点击打开有界的完整预览，不会顺带展开整卡。底部仅保留省略、源结果限制和续读说明。Fullscreen 使用 `Expand` / `Collapse`，正文保持可拖选；普通终端保留原生快捷键提示。展开后的 Input / Output 需要额外预览时，在各自分区标题提供 `Open preview`；鼠标收起来源工具卡或其所在分组时，对应预览同步关闭，拖动选择文本时保留预览。工具尚未返回结果时，展开也可查看受限的 Input；运行中还没有输出时，展开的 Output 显示等待提示，不被当成已完成的空结果。Read 的 `More available · offset=…` 单独表示下一次读取位置；窄屏优先保留完整操作提示，过窄时省略提示，仍可使用配置的展开快捷键。

失败使用 `✗` 和错误色；已确认取消使用中性 `–`，标题、折叠/展开正文与展开背景均不按失败标红，模型回合中止提示也使用中性色。Pi 原生取消即使附带 `isError`，仍按取消展示，保留原始结果和取消原因；失败与取消均保留已取得的部分输出。普通输出中的 “abort” 或业务状态不作为取消依据。未知任务生命周期保持未知，任务顺利执行但发现问题时，结果中仍显示问题。后台任务的标题与展开背景读取同一实时状态，历史缺少耗时、用量或状态时不补写。发送指令和请求取消的成功回执不等于子任务已经完成。

第三方显式声明自绘 `self` 外壳并提供渲染器时，保留其原组件、鼠标行为和独立布局；普通工具使用统一外壳，展开时可复用其可用原生结果视图，展示失败则回退有界内容。非工具 widget 和自定义 UI 保持原扩展的交互。所有预览只处理展示，不修改执行参数、原始消息或结果，不调用模型生成摘要。

TUI 的正文背景由终端决定，主题中的页面底色用于 HTML 导出。Shell 输入目前按整段输入着色，已有代码高亮继续保留，不额外解析 Shell 语法。

通用工具和 MCP 标题的 JSON 参数摘要先限制字符串、条目数和嵌套深度，再序列化；超出预算以 `…` 标记，避免为一行标题完整序列化大参数。此限制只作用于摘要，不修改执行参数、会话记录或既有的展开 Input；已有命令、路径和查询等专用摘要保持原有规则。

对象参数的展开判定只检查顶层可显示字段，避免仅为显示展开提示而格式化完整的嵌套内容；空白代码块、数组和其他特殊输入保留原有判定。展开后的 Input 格式和长度限制保持原有规则。

Footer 费用包含消息、工具结果、压缩、分支摘要及缓存预热等独立 `usage` 记录中的实际费用。上下文与费用统计在重绘间复用，流式期间最多约每秒重新统计一次；切换会话、历史位置、模型或 Thinking Level 时立即刷新，避免长会话在每次重绘时遍历全部记录。Git 操作状态通过 Git 实际元数据及文件变更事件更新，并在工具或 Agent 结束时补查，支持 worktree；不定时轮询、不查询增删行数。监听、短暂合并事件的计时器和未完成的目录查询会随 Footer 释放或会话关闭清理。

Fullscreen 下，原生工具预览中的 `ctrl+o to expand` / `to show more` 提示也支持鼠标展开；有明确展开提示时，正文点击不会误展开，未提供提示的卡片保留原生点击行为。展开时若点击的行已在视口下半屏，视口保持底部跟随、由新内容顶上来；其余位置照旧冻结视口，点击行留在原处。

Bash 的退出码和耗时只显示实际返回或记录的数据。Pi 重载或恢复历史时可能不再提供成功结果的结构化退出码，此时省略退出码，不补写 `exit 0`；有记录的耗时及原生错误原因照常保留。展开复用已有 Input / Output 视图与全量预览，无法恢复工具本身未保留的输出。

搜索摘要只统计实际显示的匹配行或路径，不把上下文行和限制说明算进结果。达到上限或被截断时明确标记已显示的数量，完整的原生提示仍可展开查看。Read 的完成范围根据返回内容与原生续读提示确认，不使用请求的 `limit` 充当已读取行数；图片和超长首行提示分别显示，不计为文件内容。展开的工具分组保留 Kitty / iTerm2 内联图片占用的空白行，后续工具的鼠标命中位置与显示行保持一致。错误、无法识别的范围和只有元数据的结果保留真实内容；SoL-Pi 已替换为存储占位符的历史结果显示 `Stored result`，不把摘录当作完整结果计数。

## 配置

固定工具渲染模式为 `on`，Footer 固定为单行无图标。不再提供 `/ccstyle` 设置面板，也不读取旧的 `~/.pi/agent/pi-cc-extensions.json`。

仅修改仓库根目录的 `simplify.json`：

```json
{
  "diff": { "view": "auto", "collapsedEditLines": 12 },
  "thinking": { "previewLines": 3, "completedPreviewLines": 1 }
}
```

`thinking.previewLines` 控制运行中的思考预览，`completedPreviewLines` 控制完成后的预览；两者支持 0–15 行，`0` 只保留标题与展开入口，`completedPreviewLines: null` 跟随运行中的行数。修改后执行 `/reload` 生效。

Diff 在省略标记处重新开始语法高亮，避免省略前未闭合的注释或字符串影响后续片段；整个 Diff 仍共用原有高亮字符预算。

配色通过 `themes/simplify-dark.json`、`themes/simplify-light.json` 修改。

## 与 SoL-Pi 一起使用

本扩展**不会重新注册或接管 `write` 工具**。写入前的文件快照由 `tool_execution_start` 事件读取，路径解析复用 Pi 原生规则，支持相对路径、`~`、前缀 `@` 和 Unicode 空格；展示层仅使用这些快照渲染 Write Diff，因此不会与 SoL-Pi Action Fusion 争夺 `write` 的工具所有权。

如果写入前的内容无法安全读取、写入执行失败或上游工具没有提供可比较数据，则回退普通结果显示。执行结果完全由 Pi / SoL-Pi 决定。真正的取消、压缩与错误信息不会被隐藏。

## 独立的官方 Subagent 后台扩展

仓库的 [`subagent/`](subagent/README.md) 维护本机官方 Subagent 示例的扩展版本，支持立即返回任务 ID、子 Agent 语义进度进入主模型上下文、运行中补充指令和任务查询/取消；父回合进行中在 Working 行尾显示运行/等待数量，回合结束后在输入框上方持续显示运行/等待状态；任务卡标题显示角色、短任务、真实状态和耗时，运行中显示进展，完成后保留结果预览，展开后按任务、详情、报告和结果分区。同批终态通知使用独立树形摘要，保留各项结果或失败/取消原因；普通进度被动进入上下文，决策和终态唤醒父模型，父回合可 `sleep`、子回合在阻塞时直接暂停推理，保留同一会话等待通信。保留同步 single、parallel、chain。要求 Pi 1.4+；独立安装，不随展示扩展自动启用。安装、用法、清理边界和真实进程测试说明见其文档。
