# 工具卡展示规范 v1（草案）

状态：**待用户评审，尚未作为开发验收基线**。Read 的四行预览及明确省略提示方向已获认可，其余样式等待统一确认；本轮只定义规范，不修改渲染实现。

各工具的分类、通用兜底与完整样式对照见[工具卡样式目录 v1](tool-card-styles.md)：六类专用卡加一种全局兜底，容器和辅助消息单独定义。

本文件覆盖工具卡、执行容器及相关消息的共同展示规则。确认后再同步到 `AGENTS.md` 的已确认约定，并按规范分批实施；确认前继续以现有约定为准。用户当前的明确指示优先。

## 1. 要解决的问题与设计原则

当前工具卡已有共同配色和部分共享组件，但没有完整的内容披露规则。例如 Read 标题显示 `lines 1–177 · Expand`，正文只预览 4 行，末尾却没有说明剩余内容被隐藏；Subagent 的短标题可能来自任务路径，结果预览可能被空行和 Markdown 标题占满。

统一规范应保证：

1. 一眼能辨认执行的工具、对象、真实状态及主要结果。
2. 看得出内容是否省略、为什么省略，以及展开能够看到什么。
3. 同一含义使用同一种表达；各工具保留有用的语义差异。
4. 不以颜色、成功图标或自动摘要代替实际结果，不额外调用模型生成展示信息。
5. 不修改原始参数、工具结果、会话记录、执行流程或工具所有权。

## 2. 展示层级

| 层级 | 展示内容 | 折叠后的职责 |
| --- | --- | --- |
| 独立工具卡 | Read、Bash、Grep、Find、Edit、Write、Update Plan、普通/MCP 工具等 | 工具名称、主要对象、真实状态、必要预览及省略说明 |
| Multiple Tools | 按现有规则聚合的一批工具 | 容器状态与二级语义摘要，不铺开每项正文 |
| Codemode | 一次代码执行及其可获得的子调用信息 | 区分容器与子调用，显示实际状态与紧凑执行树 |
| Subagent / Subagent Task | 同步单任务、并行、链式及后台任务 | 标明工具类别、角色、短任务、进展或终态结论；保持独立卡片 |
| Skill 消息 | 已加载的技能指令 | 显示技能名及加载语义，展开查看指令 |
| 后台任务 widget / 终态通知 | 独立于父回合的后台活动和结果 | 保留运行/等待可见性及实际结果，不替代任务卡 |

Skill 是指令入口，其加载卡不代表整个工作流已经执行完毕。Skill 继续调用的工具和 Subagent 各自保留真实执行卡。将整个 Skill 聚合成父容器属于另一项设计，本规范不新增这种容器。

Subagent 保持既有分组排除规则，不塞进 `Multiple Tools`。同步并行/链式任务可以在自己的任务容器内分层展示。其他工具继续按现有执行关系聚合，不能仅凭相似名称建立父子关系。

## 3. 独立卡片的共同结构

默认结构：

```text
[状态] 工具名称 · 关键摘要/状态元信息 · 实测耗时 · Expand
  主要对象（路径、命令、查询等，必要时使用）
  有界的结果/进展预览
  … 明确的省略说明（存在预览省略时）
  执行结果限制或续读说明（存在时）
```

- 标题负责身份、状态和操作；对象行负责具体执行对象；预览负责主要结果。避免重复同一信息。
- 工具类别必须可辨认。Subagent 使用 `Subagent · 角色 · 短任务`，不能只显示看起来像 Skill 名的角色。
- 耗时仅来自实测或合法历史数据。短耗时如 `12.8s`，长耗时如 `8m38s`、`1h02m`；缺少数据时省略。
- 折叠卡内部不插入装饰性空行。相邻卡片以一行空白为目标，不叠加多层组件留白；源码和原始输出中有意义的空行保留。
- 折叠态保持透明，展开态使用已有中性/错误背景和原生布局。状态不能只靠背景或颜色表达。
- 展开仍复用原生 Input / Output、语法高亮、图片及已有工具专用视图。

展开/收起操作统一固定在标题末尾，适用于全部专用卡、通用兜底卡、执行容器及可展开消息，**包括 Edit / Write Diff**。不能因运行、成功、失败、是否存在 Diff 或展开状态改变而移动到正文底部。

增删/差异统计属于标题元信息；底部只放内容省略、限制或续读说明，不放操作入口。分组二级摘要沿用父容器入口，不重复增加子项控件。

Fullscreen 使用 `Expand` / `Collapse`，不加箭头或下划线。普通终端保留配置的原生快捷键提示。省略说明不是第二个展开按钮，不重复放置控件。

## 4. 状态与结果语义

| 真实状态 | 独立工具/任务 | 容器 | 必须保留的信息 |
| --- | --- | --- | --- |
| 接收参数 / 尚未开始 | `○`，明确接收/待执行 | `○` | 已接收的中性预览，不能显示成功计数 |
| 执行中 | accent 蓝色静态 `○` | `○` | 最新进展或当前操作 |
| 等待输入 / 决策 | `○` + `waiting` | `○` + 等待说明 | 当前问题和等待对象；不能只显示 Working |
| 成功结束 | `✓` | `●` | 真实结果；默认不再重复 `completed` |
| 失败 | `✗` | `✗` | 实际失败原因和可获得的退出信息 |
| 取消 | `–` + `cancelled` | `–` + `cancelled` | 取消语义及已有实际原因 |
| 状态缺失 / 仅历史快照 | 中性文字说明 | 中性文字说明 | 不补造成功、耗时或实时状态 |

- 运行、接收参数、等待都需要文字/内容语义区分，不能仅凭同一个圆圈推断。
- 容器仍在运行时保留 `○`，同时明确显示已经失败/取消的子项；终态混合结果保留各类别计数，不用一个成功标记盖过失败。
- 成功表示工具执行完成。例如检查 Agent 成功返回“两项问题”，不等于代码检查通过。结论必须继续可见。
- Bash 的 `exit 0` 是实际退出信息，可保留；未知退出码不能由成功图标倒推。
- Update Plan 是进度卡的特例：独立主标记表示计划进度，步骤未全部完成为 `○`、全部完成为 `✓`；更新调用失败要明确显示失败。分组子行仍表示真实工具调用状态。接受的计划与接收中的中性预览必须分开。

## 5. 内容隐藏与限制：强制披露规则

`Expand` 只表示可以查看更多详情，**不能代替正文预览的省略说明**。实现时需要独立判断三个问题：是否有可展开的详情、当前预览是否省略、源结果本身是否完整；三者不能复用一个布尔值或一条提示。

| 情况 | 表达与行为 |
| --- | --- |
| 已取得的结果仅显示前部 | 在预览末尾显示 `… 173 more lines in result`；不能可靠计数则用 `… More output hidden` |
| 只显示 Bash 最新输出 | 使用方向明确的 `… 86 earlier lines hidden`，不能暗示后面还有更新输出 |
| 只显示部分条目/步骤/任务/差异 | 使用真实单位，如 `… 5 more paths`、`… 2 more steps`、`… 3 more tasks`；不把展示行数当条目数 |
| 单行/某个条目只显示了部分文字 | 文本保留可见省略符；有正文预览损失时补通用省略说明，不声称隐藏了 N 个完整条目 |
| 工具执行结果本身被限制或截断 | 保留原始限制说明；展开不能恢复未取得的内容，不写成普通预览省略 |
| Read 还有文件内容未读取 | 保留原生 `More available · offset=…`，表示下一次读取位置，与展开当前结果分开 |
| 历史结果被替换为存储摘录 | 明示 `Stored result` / 摘录状态，保留可用摘录与存储信息；不承诺展开能恢复完整结果 |
| 展开视图仍有展示上限 | 明示展示限制并保留已有可用获取方式；不能宣称已显示完整 Input / Output |

补充约束：

- 前 4 行、末 4 行、字符裁剪、列表上限及 Diff 省略都必须在裁剪时留下是否省略的信息，不能最终靠猜测补提示。
- 只有能可靠确定总量和实际完整显示量时才显示数字。折行、长行部分显示、图片、元数据、历史摘录等情况采用诚实的通用提示。
- `lines 1–177` 表示已确认的读取范围，不表示预览已经显示 177 行。
- 预览全部可见、只有 Input/Details 尚未展开时，可以仅保留标题中的展开入口；不伪造 `More output hidden`。
- 没有额外可展示内容时不显示展开入口。运行中已有详情时允许查看当前内容，未取得内容不以占位符冒充结果。
- 在有明确标题控件的卡片中，省略说明和正文不额外扩大点击区。保留拖选、滚动、路径链接与原生键盘操作。

## 6. 密度、内容选择与窄屏

默认预算按**渲染后的可见行**计算，不按字符串长度或原始 Markdown 行数计算：

| 内容 | 默认预算/选择规则 |
| --- | --- |
| 路径/命令/查询等对象 | 最多 2 行；过长时明确省略，展开保留现有 Input |
| 普通工具结果、Read/Grep/Find | 最多 4 行；Read 保留真实源码和高亮，不删除源码空行 |
| Bash | 最近 4 行输出，标明省略的是更早输出；错误/取消原因须可见 |
| Update Plan | 最多 6 个步骤摘要，优先当前步骤，省略的前后步骤均须说明 |
| Subagent 执行中/等待 | 最新 1 行进展或当前问题，长问题在有界预览内显示并保留详情 |
| Subagent 终态 | 最多 3 行有意义结论；不能让纯空行、围栏或孤立 Markdown 标题耗尽预览 |
| Subagent 多任务容器 | 最近最多 4 项，每项最多 1 行进展/结论，正文和更早任务省略分别说明 |
| 分组二级摘要 / Codemode 子项 | 默认最多 6 项，每项一行语义摘要；嵌套合计预算，超出时给出明确剩余数量/通用提示 |
| Diff、图片、交互式提问 | 保留专用布局与已有合理预算，沿用统一披露规则 |

Subagent 短任务优先采用调用方已有简短任务名；缺少时从原任务提取首个可靠的目标描述。`Active task:` 路径、协议字段和上下文前言不优先占标题。无法可靠提取时保留中性的原任务摘录，不自动翻译、编造结论或改写执行参数。

结果摘要优先展示原始结论正文；只在展示层跳过没有信息的空行、纯格式标题等，不改变原始 Markdown。没有可靠正文时保留可获得的原始内容或说明结果形态，不能默认写成“已完成且通过”。

窄屏优先保留状态、工具类别和完整操作提示，再精简对象、任务名及辅助统计。连工具名和提示都放不下时可省略屏幕提示，原生快捷键继续有效。所有截断考虑 ANSI、中文、Emoji 和终端可见列；不改变光标、点击坐标或原生 padding 来偷偷挤布局。

## 7. 各工具的语义合同

| 工具类别 | 独立卡片要回答的问题 | 二级摘要/容器内表现 |
| --- | --- | --- |
| Read | 读哪个文件、实际范围、可用内容、是否还有当前结果/文件内容未显示 | 路径与已确认范围；图片、存储摘录保持真实类型 |
| Grep | 查什么、在哪查、实际匹配及限制 | 查询、范围、匹配摘要；上下文行不计匹配数 |
| Find | 查什么路径、在哪查、实际找到多少项及限制 | 查询/范围与路径数；目录也作为路径 |
| Bash / PowerShell | 执行什么、最新输出、真实退出/耗时及失败原因 | 命令与实际耗时；失败原因保持可辨认 |
| Edit / Write Diff | 哪个文件、实际变化、预览是否省略 | 路径与差异摘要；缺少安全快照/执行失败时诚实回退 |
| Update Plan | 已接受计划的完成数、当前步骤、剩余步骤 | 仅完成数和当前步骤，展开查看完整接受的计划 |
| Subagent / Subagent Task | 什么角色做什么、在运行还是等待、结论是什么 | 保持独立；同步单个/并行/链式/后台共用语义规则 |
| Codemode | 容器执行情况、可获得的子调用及各自真实结果 | 子调用用紧凑执行树；不把派发成功当子调用完成 |
| Question / Ask | 当前问题或用户实际选择 | 提问交互由原实现负责，结果卡展示真实选择/取消 |
| **全局兜底：通用 / MCP** | 所有未适配新工具、MCP/扩展工具以及无法安全使用专用视图的结果，显示真实名称、有界输入、主要输出/错误 | 有可信语义摘要时使用，否则统一有界降级；保留真实状态与原始详情 |

专用适配数据不兼容时也必须有同一通用卡可用，不能退回缺少身份/状态的裸结果。第三方可用专用交互保留，非工具的 widget/自定义 UI 不强制转换为工具卡。分类边界、适配顺序和 Tool/MCP 样式见[样式目录](tool-card-styles.md)。

二级语义摘要不等同于正文预览，不要求为每个省略的完整结果重复增加提示。父容器提供展开入口；如果容器内实际展示了截断的正文或列表，则仍须明示省略。分组中不显示每个子项的重复展开按钮。

## 8. 对照示例（待确认）

以下是结构示意，数值和任务文字用于说明规则，不是新的实测结果或实际终端截图。`Expand` 示意 Fullscreen；普通终端替换为原生提示。

### Read：独立运行态与完成态

```text
○ Read · requested lines 1–200 · Expand
  extensions/renderer/tool/message-display.ts
  Reading…

✓ Read · lines 1–177 · Expand
  extensions/renderer/tool/message-display.ts
  import {
      BranchSummaryMessageComponent,
      CompactionSummaryMessageComponent,
      SkillInvocationMessageComponent,
  … 173 more lines in result
```

这里的 173 仅适用于已确认结果有 177 行、完整显示了前 4 行的情况。有折行或不完整行时用 `… More output hidden`。

如果工具只返回文件前 200 行，当前预览以外还有 196 行，并且文件本身也未读完：

```text
✓ Read · lines 1–200 · Expand
  src/example.ts
  [前 4 行内容]
  … 196 more lines in result
  More available · offset=201
```

前一行说明展开当前结果；后一行说明继续读文件。两者不能合并或互相替代。

展开态沿用同一标题和真实范围，操作变为 `Collapse`，正文展示已有 Input / Output；展开后自身仍有展示限制时继续明确说明：

```text
✓ Read · lines 1–200 · Collapse
  Input
    [已有路径、offset、limit 等实际参数]
  Output
    [当前可用结果，保留原生高亮与布局]
    [仅当展开视图仍被裁剪时，显示实际限制说明]
  More available · offset=201
```

示例方括号是文档注释，产品中不能以这种占位内容替代真实数据。

### Bash：独立运行态与完成态

```text
○ Bash · 12.8s · Expand
  npm run typecheck
  [最新输出，最多 4 行]
  … 86 earlier lines hidden

✓ Bash · exit 0 · 14.2s · Expand
  npm run typecheck
  [实际输出尾部]
  … 86 earlier lines hidden
```

没有较早输出被省略时不显示最后一行。失败显示实际退出码/原因；取消明确显示 `cancelled`，保留已有输出。

### Subagent：独立运行态、等待态和终态

```text
○ Subagent · trellis-implement · 实现控制台布局 · 12.8s · Expand
  正在调整页面布局与分区。

○ Subagent · reviewer · 检查登录流程 · waiting · Expand
  需要确认：此次是否检查第三方登录？

✓ Subagent · trellis-check · 检查控制台布局 · 8m38s · Expand
  Review complete. Two findings.
  [已有问题正文摘录]
  … More result details hidden
```

最后一张表示检查任务执行完成，两个问题仍清楚可见。失败/取消分别保留 `Error` / `Cancelled` 原因；没有更多结果时不显示最后一行。展开继续按 Task、Details、Reports、Result / Error / Cancelled 分区，保留原任务、实际记录及可获得的用量。

同步并行/链式的多个任务使用相同任务行与状态规则；折叠默认保留最近 4 项，剩余任务给出明确提示。后台 widget 与终态通知继续使用真实任务状态和结果，不因父回合结束消失。

### Multiple Tools：分组运行态与完成态

```text
○ Multiple Tools · 1 done · 1 running · Expand
  ├ ✓ Read · src/app.ts · lines 1–120
  └ ○ Grep · "legacy" · src/

● Multiple Tools · 2 done · Expand
  ├ ✓ Read · src/app.ts · lines 1–120
  └ ✓ Grep · "legacy" · 3 matches
```

二级不铺正文，不重复展开提示。某一子项失败但另一项仍运行时，标题保留运行语义并明示失败数量，子项显示真实错误摘要。全部结束后按真实混合结果显示终态，不能显示成功容器掩盖失败。

### Diff、Plan 与 Skill 的必要差异

```text
✓ Edit · +24 −8 · Expand
  src/app.ts
  [已有有界 Diff]
  … 2 more hunks

○ Update Plan · 2/4 · Expand
  ✓ 定位问题
  ✓ 确认数据来源
  → 调整实现
  · 验证

✓ Skill trellis-check · Loaded · Expand
```

Diff 的操作与其他卡片一致固定在标题末尾，差异仅体现在正文视图。计划更新执行完毕不代表计划全部完成。Skill 的 `Loaded` 仅表示指令已加载；其后工具和子代理的执行状态由各自卡片表达。

## 9. 当前实现与草案的差距

本节记录设计审查发现，不表示已经修复：

- Read/Grep/Find 有 4 行预览，但没有一套可靠的可见/隐藏内容说明；展开本身和续读提示不能补足这一点。
- Bash 的输出尾部、命令裁剪以及其他工具的裁剪使用不同提示；裸省略号不足以说明对象和方向。
- Subagent 已统一同步/后台的共享卡片，但任务短标题、语义预览、长耗时和工具身份仍需按共同规则收敛。
- Plan、Codemode、Diff 和 Multiple Tools 已有各自上限/省略行为，需要核对单位、真实状态、提示位置及父子层级。
- 普通/MCP 工具的有界参数摘要已有性能保护；还需统一“摘要/预览/完整详情”的边界，不能为披露信息重新遍历超大对象。
- 展开后的既有 Input 字符上限及其他展示限制需要单独核对；“展开”等于完整原始数据的承诺不成立。
- 不能仅替换几个文案就宣称统一完成；裁剪是否发生、计数可信度、显示方向、真实状态都需要可验证的数据。

## 10. 实施顺序与验收

确认本规范后再实施，不先逐个修补截图：

1. 建立共同的展示规则：状态、展开入口、预览预算、是否省略、可靠单位/数量、执行结果限制。
2. 先贯通 Read、Bash 与 Subagent，验证文件内容、实时尾部和语义结果三种场景；共同规则必须支持其余类型。
3. 应用到搜索、Plan、Diff、容器及通用/MCP 工具，保留专用语义与原生交互。
4. 对所有类型按同一矩阵验收，再更新已确认规范；不顺带重构执行系统。

验收矩阵至少覆盖：

- 独立一级、分组二级、容器嵌套；运行、等待、成功、失败、取消、未知/历史状态。
- 空结果、恰好达到预算、超出预算、长单行、折行、中文/Emoji/ANSI、空行和 Markdown 标题。
- 结果完整但预览省略、工具结果截断、Read 续读、Stored result、展开视图自身仍有限制。
- 混合成功/失败的容器；成功完成但报告问题的检查任务；尚未接受的 Plan 参数。
- 深浅主题、真彩色/256 色、40/60/110 列、普通终端/Fullscreen。
- 鼠标标题命中、正文拖选、滚动、键盘展开、输入焦点/草稿、后台 widget、`/reload` 与磁盘恢复。
- 普通重绘与活跃分组缓存保持有效，不因生成省略提示额外全量扫描会话、序列化大参数或调用模型。

源码实施按仓库要求运行安装、类型检查、测试与差异检查。真实 Pi/PTY 可验证行为，但用户实际终端的视觉验收仍须单独说明。文档草案本身只核对内容、引用及 `git diff --check`。
