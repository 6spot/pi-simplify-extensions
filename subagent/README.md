# 官方 Subagent 示例的后台任务扩展

从本机 Pi 官方示例的 `index.ts` / `agents.ts` 副本维护，要求 **Pi 1.4 或更新版本**。同步 single、parallel、chain 沿用原实现；新增后台单任务、语义报告和双向通信。不是第三方 `pi-subagents`，不修改 Pi Core 或 Trellis，也不依赖数据库或服务。

## 加载

此目录独立于 Simplify 的展示扩展，未加入根 `package.json` 的默认扩展入口。首次加载可使用：

```bash
pi --extension /absolute/path/pi-simplify-extensions/subagent/index.ts
```

已有官方示例时，应先把 `~/.pi/agent/extensions/subagent` 备份到 **extensions 目录之外**，再把该路径链接到本目录，避免同时注册两个 `subagent`。如果原路径是软链接，先记录原目标，不修改目标中的上游文件。完成安装后，现有会话需 `/reload`，新会话会直接加载。

无需增加配置。当 `subagent` 已启用时，扩展在 `session_start` 自动启用管理工具 `subagent_task`。后台子进程仅增加 `subagent_report`，不注册本扩展的派发和管理工具。

## 工具用法

下面是模型调用参数，不是 Shell 命令。`agent` 应替换为已发现的 Agent 名称。

后台派发，立即获得 `id`：

```json
{"agent":"worker","task":"检查解析器边界，完成一个有用阶段或遇到阻塞时报告","background":true}
```

管理任务：

```json
{"action":"list"}
{"action":"get","id":"任务 ID"}
{"action":"send","id":"任务 ID","message":"补充约束：保持现有 API","mode":"steer"}
{"action":"send","id":"任务 ID","message":"采用方案 A，继续完成","mode":"followUp"}
{"action":"wait","id":"任务 ID","after":2,"timeoutMs":10000}
{"action":"sleep"}
{"action":"cancel","id":"任务 ID"}
```

- `steer` 在当前工具批次执行完后、下次模型请求前应用；`followUp` 等当前工作结束后应用。空闲的阻塞子任务收到任一模式的消息都会开始下一轮，沿用原子会话。使用官方 `prompt + streamingBehavior`，避免空闲时仅入队却不启动。
- `send` 结果中的 `last_instruction` 包含实际 RPC 接受状态 `started` / `queued`；接受不等于模型已执行。若输入被子扩展处理、未入队，则返回错误。
- `wait` 等待下一个语义事件、终态或超时，默认 10 秒、上限 30 秒；`after` 使用上次返回的 `revision`。取消等待只终止等待，不取消任务。
- `sleep` 无需任务 ID。有活动任务且父 Agent 没有其他工作时，先向用户说明等待事项，再单独调用；返回官方 `terminate: true`，结束当前推理回合而不请求下一轮模型。决策、阻塞、终态事件或用户输入可以继续父会话；普通进度只被动写入上下文。有用的独立工作仍可正常执行。没有活动任务时不终止，让父模型交付已有结果。
- 查询返回 `running` / `blocked` / `completed` / `failed` / `cancelled`、启动/结束时间、耗时、最近活动、`idle_duration`（秒）、最新进度、事件历史及最终结果/错误。静默时长只是事实，不自动判为卡死。
- 同步 single / parallel / chain、后台派发与管理工具使用统一专用卡片，遵循[工具卡规范](../docs/tool-card-spec.md)。标题显示工具身份、角色、原始短任务、真实状态和已有耗时，展开提示固定在标题末尾。单任务运行中只预览一行最新进展，终态最多三行结果或错误；多任务展示最近四项，各保留一行进展或结论，并说明隐藏内容。短任务与结果从原文提取，不调用模型摘要，也不把协议上下文当作任务目标。
- 展开按 Task、Details、Reports、Result / Error / Cancelled 分区显示保留内容和已有用量。失败与取消使用不同标记，均保留已获得的部分结果；发送/取消操作的回执与目标任务状态分开。未知或不兼容的任务结果使用有界兜底，缺少历史耗时、统计或生命周期信息时不补写。同步状态来自真实进程，不能把运行中初始退出码 `0` 当作成功。
- 使用官方组件、主题和交互；与 Simplify 同用时，折叠透明、展开保留中性或错误背景，不加入普通工具分组。标题与背景读取当前实时状态；注册表淘汰任务后，同一卡片保留最后绘制状态。重载后只能读取派发快照的历史卡以 `at snapshot` 标明，不能当作当前活动状态。窄屏按可见列裁剪，优先保留状态与任务，仍可使用原生展开快捷键。
- 只要有活动后台任务，输入框上方就持续显示 `○ Background <Agent> running · <短 ID>`；阻塞时改为 `waiting for parent`，收到指令恢复后切回运行状态。主 Agent 结束当前回合不会清除此标识；任务完成、失败、取消或会话清理后才移除。使用官方独立 widget，不接管输入焦点，也不把后台标识混入主 Agent 的 Working 动画。
- 单任务完成和失败通知默认展示最多三行结果/错误预览；展开后显示保留的完整文本，失败或取消时也保留已有的部分结果。同一批投递的多个终态通知使用独立树形摘要，分别标出完成、失败、取消数量，并在各子项下保留一行实际结果或原因；决策和阻塞继续单独突出显示。通知不加入 `Multiple Tools`，也不替代独立任务卡或后台状态条。新通知保存已有任务描述和耗时，历史通知缺少的字段直接省略。与 Simplify 同用时，通知标题区分 `Background task` / `Background tasks`，Fullscreen 下使用标题末尾的 `Expand` / `Collapse`，展开后正文保持可拖选；常规模式和独立使用时显示原生展开快捷键。主 Agent 仍须向用户总结实际结果；如果还有其他活动任务，结束回复前应说明仍在运行或等待，不能用空回复代替交付。

`background` 仅支持 single。并行后台任务可多次派发，每个返回独立 ID；`tasks`、`chain` 仍是原来的同步执行模式。

项目 Agent 仍需指定 `agentScope: "project"` 或 `"both"`，默认仅发现用户 Agent。沿用原来的项目可信度和 `confirmProjectAgents` 确认逻辑，拒绝授权不会启动任务；未提供 UI 的运行模式仍遵循官方示例原行为。Agent frontmatter 的 `tools` 同时支持逗号字符串和 YAML 数组。模型优先使用 Agent 配置，否则继承父模型与 Thinking Level；工作目录、Agent prompt、原始任务和工具调用钩子注入的上下文继续传给子进程。Agent 写的是不带 provider 的旧模型名时，本扩展先在当前会话可用模型中解析为唯一的 `provider/model`；仍歧义、缺失或不可用时回退到父模型，并在卡片的进程输出中说明替换原因，不再让子进程直接因模型歧义退出。

## 语义报告与主模型投递

子 Agent 自主调用专用工具：

```json
{"kind":"progress","message":"解析阶段完成；发现空数组与缺失字段走不同路径"}
{"kind":"blocked","message":"缺少测试数据，需要父 Agent 提供样本路径"}
{"kind":"decision","message":"两种修复行为不兼容，请确认是否保留旧 API"}
```

`blocked` / `decision` 作为当前批次的唯一工具调用时，返回官方 `terminate: true`，直接停止自动续推理，保留 RPC 子进程和会话上下文等待父 Agent 的明确消息；无需再请求模型输出一条“正在等待”。Pi 只有在同批所有工具结果均要求终止时才停止，因此报告约定要求单独调用。这里的休眠是停止推理、由事件循环等待通信；进程内存仍保留。`progress` 继续当前工作，不终止子回合。最终结果使用正常 assistant 最终回复；以 `agent_settled` 判定结束，避免把仍有后续工作的一轮 `agent_end` 当成完成。子进程错误、无最终文本、交互 UI 请求或异常退出均按实际情况报告失败。

路径为：`subagent_report` → 官方 `appendEntry` → RPC `entry_appended` → 父任务注册表 → 官方 `pi.sendMessage` → 主模型后续上下文。普通进度使用 `triggerTurn: false`，更新卡片和上下文但不唤醒父模型；决策、阻塞及未处理的终态使用 `triggerTurn: true`。它不依赖工具的 `onUpdate`，也不需要模型或定时器轮询任务。父模型空闲时可被唤醒；忙碌时先在扩展内保留并合并事件，等 `agent_settled` 后才投递，避免把旧进度逐条排入官方 follow-up 队列。报告标注为子任务数据，不是新增用户指令。

报告基于模型对工作的判断，不由工具次数、计时器或百分比生成。后台工具活动只更新时间。相同报告与重复序号被去重；完成结果会替换该任务尚未投递的旧进度和旧决策。通过管理工具已经取回的事件不会再次唤醒模型；已查询的终态结果仍留下可见通知，但 `triggerTurn: false`，避免额外的空确认回合。不把父模型回复自动回传给子任务，避免互相触发。每任务自动发送最多 20 条普通进度，在保留决策/阻塞余量后，非终态通知总上限为 40；超限仍更新可查询的状态及历史，`auto_reports_suppressed` 记录抑制数量，保留期内的终态始终留下可见通知。

## 边界与清理

- 当前会话最多 4 个活动后台任务（阻塞也占位），保留最多 32 个任务；达到上限时淘汰最早的终态任务，同时清理该旧任务尚未投递的通知，避免父模型持续忙碌时队列无限增长。
- 每任务保留最近 16 条事件，报告正文限制 2,048 字符，最终结果限制 32 Ki 字符；截断有明确提示。完整大型产物应写入文件并报告路径。
- 任务与报告不跨重启恢复。正常退出、会话切换和 `/reload` 释放注册表、待投递事件、临时 prompt 和子进程。宿主被 `SIGKILL` 或断电无法执行生命周期钩子。
- 薄 RPC 层只负责请求关联、有限缓冲、退出通知和进程清理，Agent Runtime 与队列由官方 Pi 实现。请求接受超时 15 秒，不限制任务总时长；自动模型重试期间也不会用静默判失败。
- POSIX 用独立进程组回收 Pi 和未自行脱离进程组的工具子进程，先 TERM、再 KILL。Windows 仅回收直接子进程，未承诺完整进程树回收。
- 后台无交互终端；需要 select/confirm/input/editor 的子扩展会让任务明确失败，不会无限等待。普通通知和状态更新不会导致失败。
- Agent 的语义报告依赖模型遵循指令；本扩展不保证报告频率，也不会用虚构进度补齐。Trellis 本身未被修改；测试验证的是原有 `tool_call` 上下文注入链路，而非未安装的 Trellis 插件端到端验证。

集成测试启动真实 Pi CLI、真实子进程和本机确定性 HTTP 模型服务，检查 **实际主模型请求**含语义进度、决策和最终结果，验证 busy steer、blocked followUp、同步 single/parallel/chain、任务隔离、异常退出、Bash 子进程取消和重载清理。授权拒绝、YAML tools、等待取消、重复阻塞状态和消息竞态另有回归测试。另验证主回合结束后后台状态继续可见、等待/恢复/终态切换、过期决策合并、已查询终态不再唤醒模型、多行结果默认可见和会话切换清理；覆盖查询恰好发生在进程清理期间的竞态，以及持续忙碌时待投递通知的保留上限。

集成测试使用实际 Pi 1.4，并计数发往本地确定性模型服务的 HTTP 请求：父 Agent 调用 `sleep` 后不再续推理，普通进度不增加父请求；子 Agent 提交决策后不追加“等待”推理，空闲期间父子请求数均不增长，显式 `send` 只恢复同一子会话一次。渲染回归覆盖 Simplify 与官方工具组件同用、无结果/无报告时展开、状态在已结束派发卡中更新、中文窄屏、失败和取消。

本次还使用实际安装路径及现有 `magpie/group/openai` 在线模型完成了临时目录任务：子 Agent 读取文件核验两项事实，主动报告进度、请求语言决策，主 Agent 发送 `USE_ENGLISH` 后，同一子任务给出正确最终摘要。本次休眠改动另作了一次在线验证，父 Agent 在派发及补充指令后分别调用 `sleep`，最终收到正确结果并向用户总结；全程只派发一个子任务，没有轮询管理工具，测试进程和目录均已清理。这证明本次运行链路可用，不保证所有模型都遵循报告约定。后续还使用实际 Pi 交互模式、Simplify 展示扩展和本机确定性模型，在伪终端中确认深浅主题下运行中卡片可用鼠标展开、折叠，键盘展开有效，任务/语义报告分字段显示，主回合结束后后台行仍显示，等待/恢复切换、多行最终结果及主 Agent 最终总结可见，输入草稿保留，终态后台行清除，且 `/reload` 成功。伪终端记录不能代表用户实际终端的字体和视觉效果，后者仍需人工验收。
